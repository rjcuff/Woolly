title: Projects
description: Keep notes about each codebase with that codebase, and facts about you everywhere.
---

Some memories are about you, like your name or how you like answers written. Others only matter in one codebase, like "acme uses Postgres 17" or "run `make dev` to start the notes app". Woolly keeps the two apart.

- **Facts about you** have no project. Every app sees them, in every folder.
- **Facts about a project** belong to that project. Apps working in it see them, and apps working anywhere else don't.

So when you open Claude Code in `acme`, it gets your preferences plus the acme notes, and nothing about your other repos.

## How the project is chosen

The project is the name of the git repo you're working in. For example, anything under `~/code/acme` is in the `acme` project.

AI apps decide when to save a fact to the project. Woolly tells them which project they're in and asks them to keep facts about you global. If an app saves something to the wrong place, edit it on the [review page](/docs/review) and change its project, or clear the project to make it apply everywhere.

Outside a git repo, apps see everything, as before.

## What each app sees

| Where | What it gets |
| --- | --- |
| Claude Code at startup | Your profile, plus the current project's notes. See [Memory that loads by itself](/docs/connect#memory-that-loads-by-itself) |
| `recall` from an MCP app in a repo | Your memories plus that project's |
| `get_profile` | Your profile, plus the current project's notes |
| `woolly profile` | Only facts about you |

Keys only clash within a project. A `database` key in `acme` never replaces the `database` key in another repo.

## From the command line

```sh
woolly remember "Deploys with Fly" --project acme
woolly list --project acme
woolly recall "how do we deploy" --project acme
```

## Decisions

Agents tend to suggest what you already turned down. A decision memory records the choice, why, and what was rejected:

```sh
woolly decide "Use in-memory rate limiting" --why "one server is enough" --rejected "Redis: overkill for one server"
```

Connected AI apps save decisions too, with the `decide` tool. Every session in the project starts with an **Already decided** list and is told not to suggest a rejected option again unless you bring it up. Give a decision a `--key` and a later decision on the same thing replaces it, with the old one kept in History.

## Notes that know when they're out of date

When a project note is saved in a git repo, Woolly records the commit. If a file the note mentions changes after that, the note is marked at the start of the next session, like *may be out of date: api/ratelimit.go changed in 2 commits since*, so the agent checks before relying on it.

## Share with your team

```sh
woolly share
```

Run it inside a repo, then commit the new `.woolly/` folder. It holds the project's memories as plain files. When a teammate with Woolly works in the repo, their AI tools start with the same notes, and new project notes they save land in the folder too. No cloud, no account.

- Only notes about this project are written to the repo. Facts about you and handoff notes never are.
- Notes from a repo are checked like anything an app saves: passwords, keys and text that reads like instructions to an AI are skipped.
- `woolly share --agents-md` also keeps a short Project notes section in `AGENTS.md`, so tools that read it without MCP, like Codex and Copilot, get the notes too.
- `woolly share --stop` removes `.woolly/` and the `AGENTS.md` section. Memories on your computer stay.

## Set the project yourself

Set `WOOLLY_PROJECT` to use a different name than the repo's, or to give a folder that isn't a git repo a project.
